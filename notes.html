01 / DETECTION ENGINEERING

A successful block.
A missing alert.

ProjectX · documented lab investigation

Symptom

The Finance file screen blocked an inert with an executable filename file. The expected custom Wazuh alert did not appear.

Investigation

The Windows source event existed: SRMSVC event 8215. I traced the event through collection and rule matching instead of assuming the preventive control was at fault.

Change and verification

Correcting the custom rule’s parent to 60601 aligned it with the warning event. A fresh test correlated event record 1312 with Wazuh rule 100201, level 10, in central evidence.

Lesson

Test the source event, transport and rule match as separate stages. A working preventive control does not guarantee a working detection pipeline.

02 / IDENTITY RECOVERY

Two states.
Two checks.

ProjectX · workstation recovery

Symptom

PX-WS01 rejected domain admin elevation with a failed trust relationship. The stored LAPS password also did not match the expected local sign in result.

Separate the dependencies

Local administrative access allowed the computer secure channel to be repaired and checked again. LAPS retrieval metadata and the local account’s password timestamp required separate review.

Recovery evidence

The secure channel check returned a healthy result. Later LAPS metadata showed a fresh password update with successful decryption, and the workstation session identified as PX-WS01\LocalAdmin. Computer policy results included the Windows LAPS GPO.

Lesson

Domain trust, policy application, directory password backup and local authentication are related. but each needs its own verification.

03 / NETWORK DESIGN

A diagram is
a starting point.

ProjectX · design review

Observation

The lab separates CORP, SERVER and DMZ. That topology explains routing but does not, by itself, prove least privilege enforcement.

Review boundary

Broad SERVER rules remain in the reviewed configuration. Hosts on the same subnet normally exchange traffic without crossing the gateway. Passive sensors only inspect the traffic actually delivered to them.

Next test

Create a source, destination, service and business purpose matrix. Validate both permitted and denied paths, and confirm that monitoring sees the expected traffic. This improvement remains planned.

Lesson

Document the enforcement point and visibility limit, not just the line between two boxes.
