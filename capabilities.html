Vulnerability assessment
and reporting.

Agreed scope · Validated findings · Practical remediation

I can prepare vulnerability assessment reports that help teams investigate issues raised during audits. I identify affected assets, review scan results and document the evidence, risk and recommended remediation. Follow up checks establish whether a change resolved the finding.

For company environments, testing starts with permission, an agreed asset scope and suitable scan settings. Tool choice depends on access, licensing and the systems being assessed.

Proposed assessment toolkit

NmapHost and service discovery within the approved network scope.
Nessus or Greenbone OPENVASVulnerability scanning and review of patch or configuration findings.
PingCastleActive Directory security assessment and review of directory risks.
ZAPApplication assessment when a website is explicitly included in scope.

These are proposed tools for scoped assessments. They are not a claim of completed customer engagements or demonstrated experience with every product.

What the report includes

  • Scope, methods and assessment limitations
  • Affected assets and supporting evidence
  • Severity rationale and business impact
  • Prioritized remediation and verification results

A scanner alert requires validation. It does not automatically establish exploitation, an audit failure or a complete assessment.

SIEM and network
log investigation.

Wazuh · Security Onion · Event correlation

I can investigate endpoint and network logs using Wazuh and Security Onion. I review alerts, compare related events and build a timeline to understand what happened. My notes explain the evidence, likely cause, limits of visibility and recommended next action.

How I approach an investigation

  1. Identify the host, account, time window and alert context.
  2. Compare the alert with source events and related activity.
  3. Separate observed facts from assumptions and missing data.
  4. Document the conclusion and further checks required.

ProjectX demonstrates a documented FSRM event investigation in Wazuh. I corrected the rule relationship and correlated a fresh source event with the central alert. Security Onion is part of the lab’s monitoring stack; a separate complete investigation case is not claimed here.

Local infrastructure.
Cloud integration.

Microsoft Azure · Identity · Operations

I can help connect local infrastructure with Microsoft Azure to support a hybrid environment. My approach considers identity, connectivity, access permissions, monitoring and recovery, with implementation steps and validation recorded in the handover.

Implementation considerations

  • Inventory local servers and identify workloads that should remain local.
  • Plan cloud management and identity integration around operational requirements.
  • Define permissions, logging and recovery responsibilities.
  • Validate the connection and document ongoing support requirements.

Azure Arc supports Azure management of servers that remain outside Azure. It does not itself migrate a workload or establish private network connectivity. Those are separate design decisions.

ProjectX retains earlier Azure milestones as historical context. Its current documented scope is the local domain lab. AZ-104 is in progress and SC-500 is planned.
