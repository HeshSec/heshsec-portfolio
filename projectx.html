CASE STUDY / INDEPENDENT PERSONAL PROJECT

ProjectX.
Architecture and validation.

A seven VM lab designed and implemented to connect identity, departmental data, network boundaries and endpoint telemetry, with documented verification and limitations.

ROLEDesigner & implementer
ENVIRONMENTVirtualBox learning lab
SCOPE7 VMs · 3 network zones
VALIDATED CASEFSRM → Wazuh

01 / THE REQUIREMENT

Protect the workflow.
Preserve the evidence.

A small organization needs directory managed endpoints, controlled departmental access and enough visibility to investigate suspicious activity. I built ProjectX to practice those dependencies together.

The design uses a pfSense boundary between CORP, SERVER and DMZ networks. Active Directory and Group Policy provide centralized Windows administration. FSRM screens departmental files, while Wazuh collects endpoint events for investigation.

My work includes the build, control configuration, troubleshooting, recovery checks and documentation. This is an independent lab, not a customer production deployment.

04 / VERIFIED INVESTIGATION

From a missing alert
to a correlated result.

01 / TEST

The file was blocked.

A harmless text file with an executable extension tested the Finance file screen. FSRM denied it and recorded SRMSVC event 8215.

02 / DIAGNOSE

The alert was missing.

I followed the source event and rule hierarchy. The custom rule needed to match warning parent 60601.

03 / VERIFY

The chain matched.

A fresh event, record 1312, correlated with rule 100201 at level 10 in the manager and dashboard evidence.

What this proves

FSRM performed the block and Wazuh produced the central alert for this test. It does not establish automatic remediation or validate all six custom rules.

05 / ENGINEERING JUDGMENT

The limitations
belong in the handover.

Same subnet, different boundary

SERVER hosts communicate locally without normally traversing pfSense. Host firewalls and service permissions remain important even with network segmentation.

Configured is not fully tested

Six custom rules passed configuration validation. One FSRM path has a fully correlated test in this public case study. Other rules need their own controlled positive and negative tests.

Recovery is part of the design

The workstation’s domain trust and LAPS state required separate recovery checks. A successful trust repair alone did not prove the stored local password was current.

Next improvement

Narrow the broad SERVER permissions with a documented dependency matrix, then validate allowed and denied paths before treating the boundary as hardened.
